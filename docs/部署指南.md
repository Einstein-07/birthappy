# BirtHappy 免费部署指南

本指南把 BirtHappy 部署到 **Vercel Hobby（免费）**，数据库使用 **Turso Cloud 免费额度**。部署完成后你会得到一个 `https://<项目名>.vercel.app` 的公网地址。

> 状态说明：截至 2026-10，Vercel Hobby 为 $0/月，适合个人、非商业项目；Turso Free 为 $0/月、无需信用卡。免费额度和规则可能调整，请以官网当前页面为准：
> [Vercel Pricing](https://vercel.com/pricing) · [Turso Pricing](https://turso.tech/pricing)

## 0. 部署架构

```text
浏览器
  │
  ▼
Vercel（Next.js 应用、API、服务端渲染）
  │
  ▼
Turso Cloud（托管 libSQL / SQLite）
```

项目在本地默认使用 `data/birthhappy.db` 文件；生产环境读取 `TURSO_DATABASE_URL` 后自动切换到 Turso。头像以二进制形式存进数据库，因此**不需要额外的对象存储**，也不依赖第三方图床。

## 1. 准备

需要：

- 一个 GitHub 账号。
- 一个 Vercel 账号（可直接用 GitHub 登录）。
- 一个 Turso 账号（可直接用 GitHub 登录）。
- 本机 Node.js 20.9+（推荐 22 LTS）。

先在本地确认项目能运行：

```bash
npm install
npm run dev
```

打开 <http://localhost:3000> 能看到首页即可。

## 2. 把项目推送到 GitHub

在项目根目录执行（把 `<你的用户名>` 换成自己的 GitHub 用户名）：

```bash
git init
git add .
git commit -m "feat: BirtHappy"
git branch -M main
git remote add origin https://github.com/<你的用户名>/birthappy.git
git push -u origin main
```

如果仓库还没创建，先在 GitHub 新建一个空仓库 `birthappy`，不要勾选初始化 README，再把上面的 `git remote add` 和 `git push` 执行一遍。

确认以下文件**没有**被提交：

- `.env.local` / `.env`
- `data/`（本地 SQLite 数据库）
- `node_modules/`
- `.next/`

项目的 `.gitignore` 已经处理好了。

## 3. 创建 Turso 数据库

### 方式 A：网页控制台（推荐）

1. 打开 <https://turso.tech>，用 GitHub 登录，进入 [Dashboard](https://turso.tech/app)。
2. 点击 **Create Database**，名称填 `birthappy`。
3. 区域（Location）选择离你的主要访问者较近的位置；如果你会调整 Vercel 函数区域，尽量让两边靠近，以降低数据库延迟。
4. 创建后打开数据库详情，复制 **Database URL**。它看起来像：
   ```text
   libsql://birthappy-xxxxx.turso.io
   ```
5. 在数据库的 Tokens / Credentials 区域创建一个访问令牌（Token），复制保存。令牌通常只显示一次。
6. 记下两项：
   - `TURSO_DATABASE_URL` = 上面的 Database URL
   - `TURSO_AUTH_TOKEN` = 刚创建的 Token

### 方式 B：CLI

安装 Turso CLI 后（安装方式见 [官方文档](https://docs.turso.tech/cli/installation)）：

```bash
turso auth login
turso db create birthappy
turso db show birthappy --url
turso db tokens create birthappy
```

不同版本的 CLI 参数可能变化，以官方文档为准。

> 你**不需要**手动建表。应用首次连接数据库时会自动、幂等地创建 `users`、`blessings`、`cake_cuts` 表。

## 4. 生成 AUTH_SECRET

登录 Cookie 由 `AUTH_SECRET` 签名，生产环境必须设置，至少 32 个字符。

**macOS / Linux：**

```bash
openssl rand -base64 32
```

**Windows PowerShell：**

```powershell
$rng = [System.Security.Cryptography.RandomNumberGenerator]::Create()
$bytes = New-Object byte[] 32
$rng.GetBytes($bytes)
[Convert]::ToBase64String($bytes)
```

复制生成结果。不要使用示例值，也不要把它提交到 Git。

## 5. 在 Vercel 部署

1. 打开 <https://vercel.com/new>。
2. 选择 **Import Git Repository**，授权 GitHub 并选择 `birthappy` 仓库。
3. Framework Preset 会自动识别为 **Next.js**，Build Command 保持默认 `npm run build`，Install Command 保持默认 `npm install`。
4. 展开 **Environment Variables**，添加：

   | Name | Value | Environments |
   | --- | --- | --- |
   | `TURSO_DATABASE_URL` | `libsql://...turso.io` | Production |
   | `TURSO_AUTH_TOKEN` | Turso 令牌 | Production |
   | `AUTH_SECRET` | 上一步生成的随机字符串 | Production |

   如果希望 Preview 部署也能使用，可以额外添加 Preview；建议为预览环境单独建一个 Turso 数据库，避免预览数据写入正式库。

5. 如项目设置里可以选 Node.js 版本，选 **22.x**（Next.js 15 支持 Node 20.9+）。
6. 点击 **Deploy**，等待构建完成。
7. 打开 Vercel 给出的地址，例如：
   ```text
   https://birthappy-xxxx.vercel.app
   ```

Vercel 的详细环境变量说明见 [官方文档](https://vercel.com/docs/environment-variables)。

## 6. 上线后的验收

按顺序检查：

1. 打开首页，应该能看到 `BirtHappy` 首页。
2. 点击「写下我的生日」，注册一个测试账号：
   - 账号：`test_birthappy`
   - 密码：至少 8 位
   - 生日：把生日设为**今天**（北京时间）
3. 注册后进入「我」页，应显示刚写的称呼。
4. 退出登录，回到首页，应该能看到这个今日生日用户。
5. 用另一个账号登录，给这个用户点「送一块蛋糕」，按钮变为「已送达」。
6. 回到测试账号的「我」页，点击「切蛋糕」，应显示已回应的数量。
7. 刷新页面，祝福统计、匿名开关、头像都应正确持久化。

数据库表在第一次访问时自动创建。如果首页能开但注册失败，优先检查 Vercel 的 Environment Variables 是否拼写正确，以及 Turso Token 是否仍有效。

## 7. 本地连接线上数据库（可选）

如果想让本地开发环境连 Turso：

1. 在项目根目录创建 `.env.local`：
   ```dotenv
   TURSO_DATABASE_URL="libsql://...turso.io"
   TURSO_AUTH_TOKEN="..."
   AUTH_SECRET="..."
   ```
2. 重新启动 `npm run dev`。

⚠️ 不要对线上数据库执行 `npm run seed`。种子脚本默认会拒绝远程地址，只有显式加上 `--force` 才会写入。正式环境请从注册页创建真实用户。

### 部署新版本

```bash

```

Vercel 会自动重新部署。也可以在 Vercel 项目的 **Deployments** 页面手动 Redeploy。

### 回滚

在 Vercel **Deployments** 中选中之前的成功版本，点击 **Promote to Production** 或 **Redeploy**。

### 数据备份

- Turso 控制台提供数据库管理能力，可在数据库详情页导出或使用 Shell。
- 也可以定期用 Turso CLI 导出 SQL。命令参数可能随版本变化，请以 `turso db shell --help` 为准。
- 头像存在数据库里，所以数据库备份会同时包含账号、祝福和头像。

## 9. 常见问题

### 注册或登录时提示「暂时无法完成注册」/「暂时无法登录」

按顺序检查：

1. Vercel 的 `AUTH_SECRET` 是否缺失或短于 32 个字符。
2. `TURSO_DATABASE_URL` 是否以 `libsql://` 开头，没有多余空格或引号。
3. `TURSO_AUTH_TOKEN` 是否完整、未过期。
4. Vercel Functions 日志里的具体报错（Project → Logs）。
5. 修改环境变量后，需要重新部署才会生效。

### 登录成功但刷新后又是未登录

- 确认访问的是 `https://` 地址，而不是用 HTTP 访问生产域名。
- 不要把生产环境的 `AUTH_COOKIE_SECURE` 设为 `false`。这个变量只用于本机用 HTTP 跑生产构建测试。

### 首页可以打开，但数据库没有表

- 首次请求会触发建表。打开一次首页/注册页后查看 Vercel 日志。
- 如果连接的是错误的数据库，确认 `TURSO_DATABASE_URL` 属于新建的 `birthappy` 库。
- 应用建表失败时不会静默吞错，日志中会有 create table 相关错误。

### 上传头像失败

- 支持 JPEG、PNG、WebP；原图最大 12MB。
- 浏览器会居中裁切为 512×512 并压缩；如果仍提示过大，请换一张更简单的图。
- 头像接口返回 404 说明该用户没有头像，这是正常状态。

### 访问 Vercel 域名很慢

- 尽量选择离主要访问者近的 Turso 区域。
- Vercel Hobby 的函数区域默认可能不在亚洲；可在 Vercel 项目设置的 Functions / Regions 中调整为靠近用户和数据库的区域（不同套餐的可用区域可能不同）。
- 免费计划有冷启动，首次请求慢几百毫秒到数秒属于常见现象。

### 能否绑定自己的域名

可以。在 Vercel 项目 **Settings → Domains** 添加域名，按提示配置 DNS。域名本身可能收费，但 `*.vercel.app` 地址免费。

## 10. 安全与运营提醒

- 本项目没有找回密码功能。请提示用户保存好密码；上线前建议准备一个管理员手动处理账号问题的流程。
- 不要将 `AUTH_SECRET`、Turso Token、`.env.local` 提交或截图公开。
- 轮换 `AUTH_SECRET` 会让所有现有登录会话失效，这是正常的。
- Vercel Hobby 仅适合个人、非商业项目；如果用于商业运营，请查看[Vercel 的使用条款](https://vercel.com/legal/terms)并升级合适计划。
- 头像与用户资料会公开出现在首页，请在产品文案中明确隐私边界。
- 若要面向陌生人公开运营，请补充内容审核、举报、限流、账号恢复和隐私政策。
