# BirtHappy 维护手册

> 项目目录：`D:\Daily\AI-projects\BirtHappy`  
> 生产地址：https://birthappy.netlify.app  
> 代码仓库：https://github.com/Einstein-07/birthappy  
> 托管：Netlify  
> 数据库：Turso（数据库名 `birthappy`）  
> 最后更新：2026-10-31

本手册用于让网站能够长期维护。不要在这里记录任何密码、Turso Token 或 `AUTH_SECRET`。

## 1. 资产清单

| 资产 | 位置 | 丢失后的影响 |
| --- | --- | --- |
| 前端/后端代码 | GitHub `Einstein-07/birthappy` | 无法继续部署 |
| 生产数据库 | Turso `birthappy` | 所有用户、祝福和头像丢失 |
| 线上托管 | Netlify 项目 | 网站无法访问 |
| 环境变量 | Netlify 项目设置 | 登录、数据库连接失败 |
| 本地开发数据库 | `data/birthhappy.db` | 仅影响本地演示，不是生产数据 |
| 备份文件 | 默认 `backups/` | 用于灾难恢复，禁止公开 |
| 修改额度 | Turso `change_quotas` 表 | 资料/生日修改次数被重置，可能被滥用 |

**必须开启两步验证：** GitHub、Netlify、Turso。保存好恢复码。

## 3. 数据库备份

### 本地开发库

默认备份 `data/birthhappy.db`：

```powershell
cd "D:\Daily\AI-projects\BirtHappy"
npm run backup
```

输出位置：

```text
backups\birthappy-backup-<时间>.json
```

### 生产 Turso 数据库

在项目根目录新建 `.env.local`（已被 `.gitignore` 排除）：

```dotenv
TURSO_DATABASE_URL="libsql://...turso.io"
TURSO_AUTH_TOKEN="你的 Turso Token"
```

然后执行：

```powershell
npm run backup
```

看到以下信息说明成功：

```text
来源：xxx.turso.io
数据：N 位用户，N 条祝福，N 次切蛋糕，N 条修改额度
文件：D:\Daily\AI-projects\BirtHappy\backups\...
```

备份包含：

- 用户邮箱、UID、UID 修改次数、密码哈希、称呼、简介、生日、匿名状态
- 头像二进制
- 所有祝福和切蛋糕记录
- 资料修改额度与生日修改额度
- 当前表结构与索引定义

当前备份格式为 `birthappy-backup-v3`，恢复脚本兼容 `v1` / `v2` / `v3`。`v1` 没有额度字段，会在应用下次访问时按规则懒初始化；`v1/v2` 没有邮箱和 UID 字段，恢复时会补列、自动生成 UID，邮箱保持未绑定，旧账号仍可过渡登录。短命的验证码、注册限流事件和每日计数器不进入备份。

> 备份包含个人资料和密码哈希。必须放在私密位置，不要提交 GitHub，不要上传公开网盘。
>
> 如果数据量很大，建议同时使用 Turso 官方导出命令：
>
> ```bash
> turso db export birthappy --output-file birthappy-snapshot.db
> ```
>
> 参考：[Turso db export](https://docs.turso.tech/cli/db/export)

## 4. 恢复数据库

⚠️ **恢复会清空目标数据库中的 `users`、`blessings`、`cake_cuts`、`change_quotas` 数据。**

### 第 1 步：先在本地测试库演练

```powershell
cd "D:\Daily\AI-projects\BirtHappy"

$env:TURSO_DATABASE_URL = "file:./data/restore-test.db"
npm run restore -- "backups\你的备份文件.json" --force
```

脚本会：

1. 校验备份格式；
2. 创建缺失的表与索引；
3. 在一个事务里清空并写入数据；
4. 核对恢复后的行数；
5. 失败时回滚数据改动。

恢复完成后检查：

```powershell
npm run backup
```

或启动本地应用验证登录、头像和祝福。

**测试完成后清理环境变量**，避免误连测试库：

```powershell
Remove-Item Env:TURSO_DATABASE_URL
```

### 本机无法连接 Turso 时：通过 Netlify 下载备份

如果本地网络无法访问 Turso 数据库节点，可使用受保护的生产备份接口。它由 Netlify 服务器访问 Turso，下载到你的电脑。

1. 在 Netlify 环境变量中添加：
   ```text
   BACKUP_TOKEN = 至少 32 位的随机字符串
   ```
   Scope 选择 **All** 或至少 Functions / Runtime。
2. 重新部署 Netlify。
3. 生成并保存 Token（示例）：
   ```powershell
   $rng = [System.Security.Cryptography.RandomNumberGenerator]::Create()
   $bytes = New-Object byte[] 48
   $rng.GetBytes($bytes)
   [Convert]::ToBase64String($bytes)
   ```
4. 下载生产备份：
   ```powershell
   $token = Read-Host "粘贴 BACKUP_TOKEN"
   Invoke-WebRequest `
     -Method Post `
     -Uri "https://birthappy.netlify.app/api/admin/backup" `
     -Headers @{ "x-backup-token" = $token } `
     -OutFile "backups\birthappy-production-$(Get-Date -Format yyyyMMdd-HHmmss).json"
   ```
5. 用本文的备份检查方法确认 `source` 是 Turso 主机，而不是 `file:`。

安全说明：

- 未配置 `BACKUP_TOKEN` 或 Token 错误时，接口返回 404。
- Token 只通过请求头传递，不要放在 URL、截图或聊天中。
- 页面不链接这个接口；它仅用于运维备份。
- 如果不再需要，可以在 Netlify 删除 `BACKUP_TOKEN` 并重新部署，接口会立即失效。

### 第 2 步：恢复正式库

先额外做一份当前生产库备份，再确认 `.env.local` 指向的是生产 Turso：

```powershell
npm run backup
npm run restore -- "backups\你的备份文件.json" --force
```

恢复后立即用无痕窗口登录一个账号，检查首页、头像和祝福数量。

### 恢复失败怎么办

- 脚本会在数据事务失败时回滚。
- 表结构创建可能已经发生，但不会删除已有表。
- 不要连续盲目重试。先保存现场日志和备份文件，再排查版本/字段不匹配。
- 如果目标库已有更新版本的字段，旧备份可能不兼容；恢复前确认备份与代码版本匹配。

### 节省 Netlify credits

Netlify 免费计划每月有 300 credits，一次生产部署约 15 credits。建议：

- 把多个小改动合并成一次提交和一次部署。
- 纯文档修改可以不急着部署，但推送仍可能触发 Netlify 构建；如不想部署，使用 `[skip netlify]` 提交信息或暂停自动部署。
- 不在生产页面反复测试无关部署。
- 每月查看用量，接近上限时减少部署。

## 5.1 修改额度

`change_quotas` 表保存两类额度：

- `profile` + `YYYY-MM`：头像、称呼、简介的当月修改次数。注册写入 `used=1`，上限 3，按北京时间月份切换。
- `birthday` + `lifetime`：生日修改次数，注册从 0 开始，上限 3。

注意：

- 无实际内容变化、只切换匿名、只改生日，都不消耗资料额度。
- 生日修改会删除该用户收到的全部 `wish`，保留 `cake_share` 和送给他人的祝福。
- 不要手工把 `used` 改小来“赠送次数”，除非你确认这是运营决定。
- 若用户投诉额度异常，先备份并查询该用户的额度记录，再决定修复方式。

## 6. 环境变量与密钥

Netlify 需要：

```text
TURSO_DATABASE_URL
TURSO_AUTH_TOKEN
AUTH_SECRET
RESEND_API_KEY
RESEND_FROM
```

可选：

```text
RESEND_REPLY_TO=reply@example.com
BACKUP_TOKEN=至少 32 位随机字符串
```

Scope 必须包含 **Functions** 和 **Runtime**，建议选 **All**。

- `RESEND_FROM` 必须使用 Resend 已验证域名下的地址，例如 `BirtHappy <noreply@your-domain.com>`。
- 未验证域名时只能用 `onboarding@resend.dev` 测试地址，通常只能发到 Resend 账户自己的邮箱。
- Netlify Functions 无法直连 QQ SMTP；v2.0.1 起统一使用 Resend HTTP API。不要恢复 `MAIL_*` 变量。
- 修改环境变量后必须重新部署。
- 轮换 `AUTH_SECRET` 会让所有用户退出登录，并让未使用的邮箱验证码失效，但不影响数据库。
- Turso Token 或 Resend API Key 泄露时立即在对应平台撤销旧凭据，生成新凭据并更新 Netlify。
- 不要把 `.env.local`、Token、`AUTH_SECRET`、Resend API Key 发到聊天、截图或 Git。

## 7. 项目可见性

Netlify 新项目默认 **Private**，匿名访问会返回 401 并跳转 Netlify 登录。

如果以后地址突然变成 Netlify 登录页：

```text
Project configuration → General → Visitor access → Project visibility
```

把 Production 改回 **Public**。

Preview 保持 Private 更安全。

## 8. 常见故障

| 现象 | 优先检查 |
| --- | --- |
| 401 / 跳 Netlify 登录 | 项目可见性是否被改回 Private |
| 500 / “刚刚有一小阵风吹过” | Netlify Functions 日志；数据库环境变量 |
| 注册失败 | Turso URL、Token、Scope、Token 是否过期；每日 100 人上限是否已满 |
| 验证码发送失败 / 503 | `RESEND_API_KEY` 是否配置，Scope 是否包含 Functions |
| 验证码发送 502 / RESEND_403 | 发件域名未验证、`RESEND_FROM` 不属于已验证域名，或测试地址收件人受限 |
| 验证码发送 429 / RESEND_429 | Resend 额度或频率限制；检查 Resend Dashboard 用量 |
| 注册返回 429 | 每日全站 100 人、同 IP 5 人、验证码频率限制；等次日/换网络或检查是否被刷 |
| 头像 404 | 该用户没有上传头像；公开页面应显示纯黑圆形 |
| 登录后刷新退出 | 是否使用 HTTPS；不要设置 `AUTH_COOKIE_SECURE=false` |
| 旧账号登录后要求绑定邮箱 | 预期行为；绑定后才能使用邮箱登录和注销验证 |
| UID 无法再改 | 每个账号只有 1 次修改机会，页面会显示已用完 |
| 首页很慢 | 查看 Netlify 函数冷启动、Turso 所在区域、Netlify 用量 |
| 部署额度耗尽 | 查看 Netlify 用量；减少部署或考虑升级 |
| 线上刚发布但内容没变 | 确认 Netlify 部署的 commit 是最新的，强制刷新无痕窗口 |

### 查看函数日志

```text
Netlify 项目 → Deploys → 最新部署 → Functions → 选择函数 → Logs
```

刷新出问题的页面后，日志会显示真实报错。提供日志给维护者时，先遮住 Token、`AUTH_SECRET` 等敏感值。

## 9. 数据模型变更规则

未来新增字段或表时：

1. 先更新 `src/lib/db.ts` 的幂等建表逻辑。
2. 新表/新索引必须使用 `IF NOT EXISTS`。
3. 对已存在的表，SQLite 无法通过简单 `CREATE TABLE` 自动加字段；需要写一次性的 `ALTER TABLE ... ADD COLUMN` 迁移。
4. 迁移代码必须可重复执行，不破坏已有数据；给旧数据回填 UID 后，再建立唯一索引。
5. 部署前先备份生产数据库。
6. 在本地 SQLite 测试通过，再推送到 Netlify。
7. 修改 `package.json` 版本号并更新 `CHANGELOG.md`；版本规则见 [版本规范](版本规范.md)。

v2.0 已新增 `users.email`、`users.email_verified_at`、`users.uid`、`users.uid_change_count`，以及 `email_codes`、`registration_events`、`daily_registration_counters`。旧库首次访问时会自动迁移并补齐 UID。

不要在未备份的情况下直接在生产库执行破坏性 SQL。

## 10. 平台迁移预案

如果 Netlify 免费政策变化或无法访问：

1. 代码仍在 GitHub，可直接导入 Vercel、Cloudflare、Render 或自有服务器。
2. 数据库仍在 Turso，不需要重新建用户数据。
3. 在新平台配置数据库、`AUTH_SECRET` 和 Resend 环境变量。
4. 如有自定义域名，把域名解析切到新平台。
5. 用备份恢复演练确认数据一致。

这就是为什么不要依赖“平台自身永不变”，而要保证**代码、数据、备份三件事可迁移**。

## 11. 当前已知限制

- 没有自助找回密码、修改密码和人工申诉后台。
- 没有评论、通知、举报审核后台；内容安全仅为基础敏感词过滤。
- 没有自动备份；备份需要手动执行。验证码和限流表不进入备份。
- 免费平台不提供 SLA，不应把它当作不可替代的唯一副本。
- 图片存在数据库里，用户数增长后需要重新评估存储。
- 邮箱验证码依赖 Resend；API Key 失效、域名未验证或额度用尽时注册会暂停。
- 站点定位是朋友间的小型应用，不适合直接开放给大规模陌生用户。
