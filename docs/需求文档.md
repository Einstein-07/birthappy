# BirtHappy 需求文档

> 版本：v2.0.1
> 更新日期：2026-11-01
> 一句话：用一块蛋糕，让今天过生日的人被温柔地记住。<br>
> 项目署名：绛河 · BirtHappy

## 1. 项目概述

BirtHappy 是一个轻量的生日祝福网站。它只在首页展示「今天」过生日的注册用户，并提供唯一的核心互动——送出一块蛋糕。没有评论区、没有排行榜、没有复杂的社交关系，只有一句被看见的生日快乐。

设计关键词：**简洁、留白、温暖、克制**。视觉以奶油白、炭黑和低饱和杏色为主，中文衬线标题与无衬线正文搭配，交互反馈轻柔而明确。

### 1.1 目标用户

- 想被朋友记住生日的普通用户。
- 想给今天过生日的朋友送上一份轻量祝福的人。
- 喜欢安静、无压力社交产品的人。

### 1.2 核心价值

1. 今天的生日被集中看见。
2. 祝福只需要一次点击，不制造社交负担。
3. 「切蛋糕」把收到的祝福变成可见的回礼，形成温柔的双向链接。

## 2. 角色与访问权限

| 能力 | 游客 | 已登录用户 |
| --- | --- | --- |
| 浏览首页今日生日列表 | 可以 | 可以 |
| 查看他人公开资料 | 可以 | 可以 |
| 注册 / 登录 | 可以 | — |
| 送出蛋糕祝福 | 不可（引导登录） | 可以 |
| 编辑自己的资料 | 不可 | 可以 |
| 切蛋糕、查看收到的祝福 | 不可 | 可以 |

说明：首页公开可浏览，便于用户把网站分享给朋友；所有写操作必须登录。生日用户本人不会出现在自己的首页列表中，避免「给自己送蛋糕」。

## 3. 信息架构

导航栏固定只有两个入口：

1. **首页**：今日生日列表。
2. **我**：个人资料、切蛋糕、收到的祝福统计。

未登录时点击「我」或「送蛋糕」进入登录页，登录后回到原目标页面。

## 4. 账号体系

### 4.1 注册（邮箱验证码）

注册字段：

- 邮箱：常用邮箱，全站唯一，统一转为小写保存；不支持一次性邮箱。邮箱不公开展示。
- 邮箱验证码：6 位数字，10 分钟内有效；通过 Resend HTTP API 发出，同一验证码最多尝试 5 次。发件地址使用 Resend 已验证域名下的 `RESEND_FROM`。
- 密码：8–72 位。
- 称呼：1–24 个字符，可填写昵称或真实姓名。
- 生日：完整日期，年份仅用于保证日期有效，**永远不会公开展示，也不会展示年龄**。
- 隐私协议：必须勾选「已阅读并同意《隐私协议》」，服务端校验 `agreed=true`。

注册成功后自动登录，系统发放 UID，并进入「我」页。注册本身计为当月第 1 次资料修改。

页面必须明确提示：

- 验证邮件由 BirtHappy 发出，页面显示当前发件地址；邮件可能被判为垃圾邮件，请同时检查垃圾箱/广告邮件。
- 请勿向任何人提供验证码，本站不会索要验证码。
- 每日最多新增 100 位注册用户。

### 4.2 登录与退出

- 登录标识为「邮箱」或「UID」+ 密码，邮箱不区分大小写，UID 不区分大小写。
- 登录态使用 HttpOnly、SameSite=Lax 的签名 Cookie，有效期 30 天。
- 退出登录后回到首页。
- 当前版本不提供自助找回密码；页面提示用户妥善保存密码，忘记密码可通过「其他 → 联系我们」联系开发者。
- 过渡兼容：v2.0 上线前只有旧账号、没有邮箱的用户，可先用原账号名和密码登录；登录后必须绑定邮箱。绑定后原账号名不再作为旧账号回退入口，但仍可能作为未修改的 UID 生效。
- 新注册用户不存在旧账号回退入口。

### 4.3 UID

- 注册成功后由系统生成，格式为 `BH` + 8 位无歧义大写字母/数字，共 10 位。
- UID 不区分大小写，保存时统一大写，全站唯一。
- 用户可自行修改 **1 次**，格式为 6–16 位字母、数字或下划线；不能使用系统保留名称。
- 页面必须始终显示剩余修改次数；已使用后明确提示「UID 仅允许修改 1 次，你已经使用过这次机会」。
- 修改成功后旧 UID 立即失效，旧 UID 可被其他用户注册/修改时使用。
- UID 修改不消耗资料修改额度。
- 注销账号后 UID 被回收。

### 4.4 每日注册上限与基础反爬

- 每日（北京时间 00:00 重置）最多成功注册 **100** 个账号；第 101 个返回 429 和明确错误码。
- 同一网络（IP 哈希）每日最多成功注册 **5** 个账号；超限返回 429。
- 邮箱验证码发送：
  - 同一邮箱 60 秒内不能重复发送；
  - 同一邮箱每小时最多 5 次、每日最多 10 次；
  - 同一 IP 每小时最多 20 次、每日最多 50 次；
  - 全站每日最多发出 500 封验证码邮件。
- 注册接口使用服务端签名的表单时间令牌，提交过快或超过 30 分钟会被拒绝；同时提供隐藏蜜罐字段。
- IP 仅保存带密钥哈希，不保存明文；限流状态保存在数据库中，适用于无服务器多实例环境。
- 每日注册上限按成功账号数计算，事务内原子占用名额，避免并发突破。

### 4.5 安全边界

- 密码使用 bcrypt 加盐哈希存储，绝不明文保存。
- 所有写接口校验登录态、参数长度与数据类型，并使用参数化 SQL。
- 写接口校验同源请求，降低 CSRF 风险。
- 上传头像仅接受 JPEG / PNG / WebP，服务端校验文件签名与体积。
- 验证码只保存带密钥哈希、有效期和尝试次数；验证码发送与注册均有限流。
- 邮箱和 UID 不公开展示；登录 Cookie 为 HttpOnly。
- 当前版本仍不提供修改密码、多设备管理、第三方登录和人工申诉后台。

## 5. 首页

### 5.1 展示内容

首页只展示**今天**过生日的注册用户，采用纵向列表。每个列表项包含：

- 头像：圆形。未上传时为纯黑圆框，不加文字、首字母或装饰。
- 公开姓名：若用户开启匿名，则显示「匿名的朋友」；否则显示其填写的称呼。
- 简介：有内容才展示；为空时**完全不渲染简介区域**，绝不显示「无」「空」「暂无简介」等占位文字。
- 生日标记：如「今天生日」。
- 唯一互动按钮：**送蛋糕**。

不展示年龄、出生年份、邮箱、UID、注册时间或祝福总数排行。

### 5.2 「今天」的定义

- 统一以 **Asia/Shanghai（北京时间）** 的自然日为准，避免服务器时区不同造成错位。
- 生日按「月-日」匹配，不比较年份。
- 2 月 29 日生日在非闰年的 2 月 28 日展示与庆祝；闰年仍在 2 月 29 日展示。
- 页面顶部展示当天日期与星期，可感知所属自然日。

### 5.3 排序与空状态

- 按注册时间升序排列，稳定、可预期；匿名状态不改变排序。
- 今日无人过生日时，展示温暖的插画式空状态和文案，不展示空白容器。
- 若登录用户自己今天生日，即便被排除在列表外，首页额外显示「今天是你的生日」提示，引导前往「我」页。

### 5.4 送蛋糕

- 每位登录用户对同一位收礼人，每个自然年最多送 1 次，重复点击不会重复计数。
- 不能给自己送蛋糕。
- 仅当对方今天生日时可送；服务端再次校验，避免绕过界面直接请求。
- 点击后按钮立即进入「已送达」状态，并有一次克制的蛋糕碎屑/星光动效；刷新后状态保持。
- 未登录点击时，跳转登录页，登录成功回到首页。
- 送出祝福后，收礼人的「收到的祝福」立即 +1（刷新后可见）。

## 6. 「我」页

### 6.1 个人资料

可编辑字段：

| 字段 | 规则 | 公开展示 |
| --- | --- | --- |
| 头像 | 可选；客户端居中裁切并压缩为 512×512；支持 JPEG/PNG/WebP；可移除恢复纯黑头像 | 是 |
| 称呼 | 必填，1–24 字符，可昵称或真实姓名 | 是（匿名时隐藏） |
| 简介 | 可选，最多 160 字符；允许为空 | 有内容才展示 |
| 生日 | 必填，合法日期，不晚于今天，不早于 1900-01-01 | 仅展示月日 |
| 匿名 | 开关，默认关闭 | 控制首页姓名展示 |

#### 匿名规则（重点）

- 匿名**只影响首页公开区域**中其他用户看到的姓名展示：显示「匿名的朋友」。
- 匿名**不影响**：
  - 本人资料中真实保存的称呼；
  - 本人在「我」页看到的称呼；
  - 登录邮箱/UID、祝福统计与切蛋糕能力；
  - 头像和简介的展示。
- 关闭匿名后，首页立即恢复展示真实称呼。
- 「我」页会提供一张公开预览卡，即时展示当前设置下他人看到的样子，避免误解。

#### 简介为空

- 编辑框可以为空。
- 首页与公开预览中不渲染任何简介节点，不出现「无」「空」「暂无」等文字。
- 「我」页编辑表单内可使用输入框占位提示，但保存后的公开区域不得出现占位内容。

### 6.2 保存

- 点击「保存资料」提交全部可编辑字段。
- 客户端做长度与日期校验，服务端做同样校验并以服务端结果为准。
- 保存成功后显示轻提示，并刷新公开预览与首页数据。
- 保存失败时保留用户输入，明确提示错误原因。
- 头像选择后先本地预览；保存时随资料一起提交。离开页面未保存则不会生效。
- 没有实际变化、只切换匿名、只修改生日时，不消耗资料修改额度。

### 6.2.1 头像、称呼、简介的修改额度

为避免恶意反复修改资料，并保持公开资料的稳定：

1. 每个自然月（Asia/Shanghai）最多允许 **3 次**资料修改。
2. 统计范围为：头像更换/移除、称呼、简介。
3. **注册本身计为当月第 1 次资料修改**。因此新注册用户在当月通常还能再修改 2 次。
4. 一次保存中同时修改头像、称呼和简介，只计为 **1 次**。
5. 以下操作不计次数：
   - 点击保存但资料没有实际变化；
   - 只切换匿名开关；
   - 只修改生日；
   - 仅查看、上传后未保存。
6. 第 1 次和第 2 次成功保存时不显示额度提示；当本月第 3 次修改成功后，提示「本月资料修改次数已用完」，并锁定头像、称呼、简介输入，直到下月 1 日 00:00（北京时间）恢复。
7. 达到上限后，服务端拒绝任何进一步的头像、称呼或简介变更，并返回明确的额度错误；匿名和生日仍可操作。
8. 并发保存时通过数据库额度行和写事务保证不会突破 3 次上限。
9. 旧月份额度记录保留用于追溯，但不再影响当前月；当前月额度按北京时间自然月独立计算。

### 6.2.2 生日修改与祝福重算

生日原则上是不可随意变更的身份信息，但为避免注册时手滑或填错，给予每个账号 **永久 3 次修改机会**：

1. 注册时设置生日不计入修改次数。
2. 每次真正改变生日消耗 1 次，共 3 次；同一日期重复保存不消耗。
3. 每次尝试修改生日都必须二次确认；服务端要求 `confirmBirthdayReset=true`，否则返回 409 预览，不写入任何数据。
4. 确认弹窗必须展示：
   - 原生日和新生日；
   - 将被移除的「已收到生日祝福」数量；
   - 切蛋糕回礼会保留；
   - 本次消耗后剩余次数；
   - 操作不可撤销。
5. 确认修改后：
   - 删除该用户收到的全部 `wish` 类型祝福（不限年份、是否已回应）；
   - 保留该用户收到的全部 `cake_share` 类型回礼；
   - 保留该用户送给别人的祝福与回礼；
   - 「我收到了多少祝福」总数按剩余记录重新计算；
   - 待回应生日祝福相应减少。
6. 每次成功修改生日后，页面和服务端响应都要展示剩余可修改次数；剩余 0 时禁用生日输入。
7. 3 次机会耗尽后，任何进一步的生日变更都被服务端拒绝。

### 6.3 切蛋糕

「切蛋糕」是生日主角对祝福的回应，也是本站第二个祝福来源。

业务规则：

1. 只有登录用户可以切蛋糕。
2. 系统找出当前用户**所有尚未回应的、别人送来的生日祝福**（不限年份，避免长期未登录导致遗漏）。
3. 每处理一条祝福：
   - 记录一条由当前用户送给原祝福者的「蛋糕回礼」；
   - 将原祝福标记为已回应。
4. 一条「蛋糕回礼」会计入**收礼人**的「我收到了多少祝福」，即使当天并不是收礼人的生日。
5. 同一对用户之间，同一种祝福每自然年最多计入 1 次；重复切蛋糕不会刷高数字。
6. 可以多次切蛋糕：每当有新祝福到来，按钮会重新可用。待回应数量为 0 时按钮禁用，并说明原因。
7. 切蛋糕本身不会增加切蛋糕者的收到数量；它只产生送给别人的回礼。
8. 操作具备幂等性：网络重试或重复提交不会造成重复计数。

交互反馈：切蛋糕成功后显示「已把蛋糕分成 N 块，回赠给曾祝福你的人」，并刷新统计与待回应数量。

### 6.4 「我收到了多少祝福」

- 主数字为收到的全部祝福总数。
- 支持「全部」与按自然年细分查看；年份按收到祝福的时间（北京时间）归档，最新年份在前。
- 计数包含：
  - 他人在首页送出的生日蛋糕；
  - 他人切蛋糕时回赠的蛋糕。
- 不单独展示送礼人身份，保护双方隐私，只呈现总数与年份分布。
- 无任何祝福时显示 0，并给出不施压的说明，不显示报错或虚假占位。
- 统计口径在页面上以简短说明呈现，避免用户误解。

### 6.5 账号与 UID 展示

「我」页必须包含账号卡片：

- 显示登录邮箱（未绑定时显示「尚未绑定」，并提供绑定入口）。
- 显示 UID 和剩余修改次数。
- 提供修改 UID 的表单或展开区域，修改前提示「只能修改 1 次、旧 UID 立即失效、不可撤销」。
- 提供退出登录按钮。
- 明确提示 UID 和邮箱不公开。

### 6.6 「其他」栏

「我」页新增「其他」区域，包含且仅包含以下入口：

1. **联系我们**：展开后显示：
   - 绛河 QQ：`3586107948`
   - 绛河の大肥鱼 QQ：`2597530663`
   - BirtHappy 用户群：`1049433315`
   - 安全提示：不要向任何人提供密码或验证码。
2. **隐私协议**：前往本机 `/privacy` 页面，展示数据收集范围、用途、第三方服务、保存期限、用户权利和联系方式。
3. **注销账号**：见 6.7。

导航栏仍然只有「首页」和「我」，不因「其他」增加顶栏入口。

### 6.7 注销账号

1. 仅登录用户可操作；必须已绑定邮箱。
2. 点击后弹出二次确认，明确列出将删除的内容：账号、UID、头像、称呼、简介、生日、收到的祝福、送出的祝福、切蛋糕记录、修改额度。
3. 点击发送验证码后，验证码发送至当前账号邮箱；用户输入 6 位验证码后确认注销。
4. 服务端再次校验验证码用途、所属用户、邮箱、有效期和是否已使用。
5. 删除在数据库事务中完成；删除成功后 UID 回收，登录 Cookie 失效，返回首页。
6. 未绑定邮箱的旧账号必须先绑定邮箱；注销后不可恢复。
7. 操作完成后，账号数据不再出现在首页和统计中。

### 6.8 称呼与简介敏感词过滤

适用范围：注册时的称呼，以及「我」页保存时的称呼和简介。服务端必须独立校验，不能只依赖前端。

过滤规则：

- 对输入做 Unicode NFKC/NFKD 规范化，去除零宽字符、变音符、空白、标点、符号和表情。
- 统一为小写，识别常见数字/符号替代写法（如 `4→a`、`1→i`、`0→o`、`@→a`）。
- 同时匹配「去除数字后的变体」，用于识别带声调数字的拼音输入。
- 对每个敏感词维护中文别名和拼音别名，防止直接用拼音绕过；例如拼音、带空格拼音和常见谐音写法。
- 使用 Aho–Corasick 多模式匹配算法，一次扫描完成全部规则匹配，避免逐词循环导致长文本性能下降。

前端：

- 输入时实时预检，显示柔和暖色警告：「输入内容包含违规词汇：xxx」。
- 存在违规词时禁用表单提交按钮；错误信息就近显示，不清空用户输入。

后端：

- 使用同一份规则再次校验，返回 HTTP 422 和明确字段错误。
- 错误信息包含命中的规范词，便于用户修改，但不返回内部规则文件或绕过细节。
- 规则文件可维护；新增词条不改变接口协议。

## 7. 页面与状态设计

### 7.1 首页状态

- 游客 + 有人过生日：可浏览列表，按钮显示「登录后送蛋糕」或在点击时引导登录。
- 游客 + 无人过生日：空状态 + 注册引导。
- 登录 + 有人过生日：可送出，已送出的按钮为「已送达」。
- 登录 + 自己今天生日：顶部生日提示 + 他人列表。
- 登录 + 无人过生日：空状态，若自己今天生日则仍显示自己的生日提示。

### 7.2 「我」页状态

- 未登录：服务端重定向到登录页。
- 新用户：头像为纯黑圆框，简介为空，显示完善资料提示。
- 待回应祝福 > 0：切蛋糕按钮可用，并显示待回应数量。
- 待回应祝福 = 0：按钮禁用，显示「暂时没有需要回应的祝福」。
- 资料额度未耗尽：不显示剩余资料次数，避免在第 1、2 次修改时打扰。
- 资料额度耗尽：显示「本月资料修改次数已用完」，锁定头像、称呼、简介，匿名和生日仍可用。
- 生日额度：始终显示剩余次数；修改时弹出二次确认；额度耗尽后生日输入禁用。
- 生日修改成功：显示本次移除的生日祝福数量及剩余生日修改次数。
- 保存中、切蛋糕中：按钮出现加载态，防止重复提交。
- 账号卡片：显示邮箱和 UID；旧账号未绑定邮箱时显示迁移提示和绑定入口。
- UID 修改后：立即更新显示，剩余次数变为 0，旧 UID 不再有效。
- 存在敏感词：字段下方显示暖色警告，保存按钮禁用；服务端仍会二次拒绝。
- 「其他」：联系我们默认折叠，隐私协议跳转新页面，注销账号打开确认弹窗。
- 注销中：按钮显示加载态；删除成功后返回首页。
- 注册页：验证码发送按钮有倒计时，发送后提示检查垃圾箱；未勾选隐私协议不能提交。

### 7.3 错误与反馈

- 表单字段就近显示错误。
- 网络或服务错误使用非阻塞提示，不清空表单。
- 所有成功反馈使用简短、温暖的文案，不使用夸张彩带或高分贝弹窗。
- 404 与未知页面提供返回首页的入口。
- 验证码错误、过期、频率限制、每日注册名额满、敏感词命中分别返回可理解的错误信息；服务端状态码以 422/429 为主。

## 8. 视觉与交互规范

### 8.1 视觉方向

- 背景：奶油白、极浅暖灰，叠加低透明度杏色光晕。
- 主色：炭黑 `#1f1d1a`；强调色：烤杏 `#d97757`、奶油 `#f6efe6`。
- 标题：中文衬线字体栈，字号大、行距舒展。
- 正文：系统中文字体栈，颜色层级清晰。
- 圆角与边框：大圆角卡片、1px 暖灰边框，避免厚重阴影。
- 不使用通用渐变按钮、霓虹色、过度玻璃拟态或满屏动画。

### 8.2 动效

- 页面内容进入时轻微上浮，间隔错开。
- 送蛋糕成功时出现局部蛋糕碎屑动效。
- 切蛋糕成功时使用轻柔的卡片提示。
- 全部动效遵循 `prefers-reduced-motion`，用户关闭动效时不做位移与粒子动画。

### 8.3 响应式与可访问性

- 适配 320px–1440px 及以上宽度。
- 移动端导航保持只有首页和「我」；列表转为纵向排列，按钮不溢出。
- 所有表单控件有可点击标签；键盘焦点清晰可见。
- 按钮、开关、加载状态提供 ARIA 状态；头像有替代文本。
- 主要文本对比度满足 WCAG AA；不仅依赖颜色传递状态。
- 支持减少动态效果设置。

### 8.4 署名规范

- 页脚版权采用大众格式：`© 年份 版权所有者 · 项目名`。
- BirtHappy 的版权所有者署名为「绛河」。
- 页脚显示：`© 2026 绛河 · BirtHappy · 以北京时间迎接每一个生日`。
- 年份自动更新；项目名仍为 BirtHappy，不替换品牌 Logo。
- 页脚以小字显示当前注册用户总数和语义化版本号（如 `v2.0.1`），不得抢占主要视觉层级。
- 用户总数每次由数据库 COUNT 查询得到；数据库异常时隐藏人数但保留版本号，不影响页面主体。

### 8.5 版本规范

采用语义化版本 `MAJOR.MINOR.PATCH`：

- **MAJOR**：不兼容的账号、数据、接口或部署变更，例如本次从账号密码改为邮箱/UID 登录。
- **MINOR**：向后兼容的新功能，例如新增页面或统计能力。
- **PATCH**：向后兼容的修复，例如样式、文案、安全修补。
- 当前版本为 `2.0.1`，完整规则见 [版本规范](版本规范.md)。

## 9. 数据模型（逻辑）

### users

- `id`：唯一 ID。
- `account`：内部唯一账号字段；旧用户保留原账号名，新用户为内部占位值。
- `email`：登录邮箱，统一小写，可为空（仅旧账号过渡期），唯一。
- `email_verified_at`：邮箱验证完成时间。
- `uid`：系统生成/用户修改一次的公开登录标识，统一大写，唯一。
- `uid_change_count`：UID 已修改次数，上限 1。
- `password_hash`：密码哈希。
- `name`：真实保存的称呼。
- `bio`：简介，可为空字符串。
- `birthday`：`YYYY-MM-DD`，年份不公开。
- `is_anonymous`：0/1。
- `avatar`：图片二进制；可为空。
- `avatar_mime`：图片 MIME。
- `created_at` / `updated_at`：UTC ISO 时间。

### blessings

- `id`：唯一 ID。
- `sender_id`：送礼人。
- `recipient_id`：收礼人。
- `kind`：`wish`（首页生日祝福）或 `cake_share`（切蛋糕回礼）。
- `year`：收礼自然年（北京时间）。
- `responded_at`：仅 `wish` 使用，表示是否已被收礼人切蛋糕回应。
- `created_at`：UTC ISO 时间。
- 唯一约束：`(sender_id, recipient_id, kind, year)`，保证不重复计数。

### cake_cuts

- 记录每次切蛋糕操作，用于反馈与问题排查。
- 字段：`id`、`user_id`、`wish_count`、`share_count`、`created_at`。

### change_quotas

- 记录资料修改和生日修改额度。
- 字段：`user_id`、`kind`、`period`、`used`、`updated_at`。
- 主键：`(user_id, kind, period)`。
- `kind='profile'` 时，`period` 为 `YYYY-MM`（北京时间月份）。
- `kind='birthday'` 时，`period` 固定为 `lifetime`。
- 资料额度上限 3；生日额度上限 3。
- 注册时创建资料额度记录，`used=1`；生日额度从 0 开始。
- 旧用户首次访问时，若当月记录不存在，按注册时间是否落在当前月初始化：当月注册计 1，否则从 0 开始。

### email_codes

- 保存注册、绑定邮箱、注销账号的验证码记录。
- 字段：`id`、`email`、`user_id`（注册时为空）、`purpose`、`code_hash`、`ip_hash`、`attempts`、`created_at`、`expires_at`、`consumed_at`。
- 验证码只保存带密钥的 HMAC 哈希，绝不保存明文。
- 有效期 10 分钟，最多尝试 5 次；新验证码会使同邮箱、同用途、同用户的旧验证码失效。

### registration_events

- 记录成功注册事件，用于按 IP 哈希和北京时间自然日执行每日注册上限。
- 字段：`id`、`user_id`、`email`、`ip_hash`、`day`、`created_at`。

### daily_registration_counters

- 记录每个北京时间自然日已成功注册的账号数。
- 字段：`day`、`used`。
- 通过事务内 `UPDATE ... WHERE used < 100` 原子占用名额，避免并发突破上限。

## 10. 非功能需求

- 首屏服务端渲染，公开首页不依赖客户端 JavaScript 才能看见内容。
- 图片压缩后保存，单张原始上传建议不超过 10MB，客户端压缩目标约 ≤ 300KB。
- 数据库结构在首次请求时幂等初始化，无需手动执行 SQL。
- 本地零配置可运行；生产使用 Turso 托管 SQLite，通过 Netlify 免费部署。
- 不需要对象存储：头像以二进制存入数据库并由专用接口返回。
- 站点不依赖第三方追踪脚本、广告或外部字体 CDN。
- 基础安全响应头、缓存策略、404 页面齐备。
- 数据库备份与恢复提供项目内脚本；备份包含用户、头像、祝福、修改额度和结构。v3 备份额外包含邮箱、UID 和 UID 修改次数；不包含短命的验证码、限流事件和每日计数器。
- 修改额度、生日重置、注册名额占用、验证码消费和账号注销必须在数据库事务中完成，失败时回滚数据写入。
- Resend API Key 和发件地址只通过环境变量提供，不写入仓库、日志或前端包。
- 页面必须提供 `/privacy` 隐私协议；注册必须勾选同意。
- 生产部署必须配置 `RESEND_API_KEY` 和已验证域名下的 `RESEND_FROM`，否则注册验证码接口返回明确的 503/502。
- 不使用 Netlify Functions 直连 SMTP：线上实测 465/587 均会超时；v2.0.1 起改用 HTTP API。

## 11. 验收标准

1. 导航栏只有「首页」和「我」，且两个页面均可正常访问。
2. 首页只出现生日为今天（北京时间）的注册用户，不出现其他日期用户。
3. 每个今日生日用户展示头像、公开姓名、非空简介和「送蛋糕」按钮。
4. 未上传头像时显示纯黑圆形，不显示字母或图标。
5. 简介为空时，首页源码与 DOM 中均没有「无」「空」「暂无简介」等文字。
6. 匿名用户首页显示「匿名的朋友」，同一用户在「我」页仍显示真实称呼；关闭匿名后首页恢复。
7. 登录用户对同一人一年只能成功送出一次蛋糕；刷新后按钮仍为「已送达」。
8. 未登录用户点击送蛋糕会进入登录页，登录后回到首页。
9. 「我」页可修改头像、称呼、简介、生日和匿名开关，保存后刷新仍生效。
10. 头像上传并保存后，首页与「我」页均更新；移除头像后恢复纯黑圆形。
11. 有未回应祝福时切蛋糕可用；切完后原祝福被标记，送出者收到可计数的「蛋糕回礼」。
12. 重复切蛋糕不会重复计数；新祝福到来后按钮再次可用。
13. 收到祝福统计包含生日蛋糕与回礼，支持全部和按年查看，年份正确。
14. 切蛋糕不能给自己刷祝福，统计不会因重复请求增加。
15. 移动端 375px 宽度无横向滚动，表单和列表可正常使用。
16. 键盘可完成登录、编辑、保存、送蛋糕和切蛋糕操作。
17. 在生产环境未配置 `AUTH_SECRET` 时拒绝启动会话逻辑并给出清晰错误，避免使用默认密钥上线。
18. 构建通过，生产模式可启动，核心流程端到端可验证。
19. 新注册用户当月资料额度已使用 1 次；连续成功修改资料至第 3 次后，出现本月额度用尽提示，头像、称呼、简介被锁定。
20. 第 1、2 次资料修改成功后不出现额度提示；无变化保存、匿名切换、生日修改不消耗资料额度。
21. 第 4 次资料修改被服务端拒绝，并返回资料额度错误。
22. 修改生日必须经过二次确认；未确认请求返回 409 且不删除祝福、不改变生日。
23. 确认修改生日后，收到的 `wish` 全部删除，收到的 `cake_share` 保留，收到祝福总数相应减少。
24. 生日每次修改后都展示剩余次数；第 3 次后为 0，第 4 次被拒绝。
25. 页脚显示 `© 年份 绛河 · BirtHappy`，年份自动更新。
26. 数据库备份包含修改额度；恢复后额度、用户、头像和祝福数量一致。
27. 未填写/填写错误邮箱验证码时不能注册；验证码过期、重复使用、错误 5 次均被拒绝。
28. 注册必须勾选隐私协议；未勾选时前后端均阻止提交。
29. 注册页明确展示当前 Resend 发件地址和垃圾邮件提示，验证码发送后有 60 秒倒计时。
30. 登录支持邮箱 + 密码和 UID + 密码，不区分大小写。
31. 注册后系统自动生成 UID；「我」页显示 UID 和剩余修改次数。
32. UID 第一次修改成功，第二次返回 429；修改后的 UID 可登录，旧 UID 失效。
33. 第 101 个当日注册请求返回 429；单 IP 第 6 个当日注册请求返回 429。
34. 称呼/简介命中中文、拼音、数字替代或去符号变体时，前端实时显示暖色警告并禁用提交；后端返回 422。
35. 「我 → 其他」展示两位开发者 QQ 和用户群；隐私协议可访问；注销账号必须通过当前邮箱验证码。
36. 注销后账号、UID、资料、祝福、回礼、切蛋糕、额度记录被删除，UID 可回收。
37. 页脚显示注册用户总数和 `v2.0.1`，人数不暴露个人身份。
38. 旧账号可用原账号名过渡登录，登录后被引导绑定邮箱；绑定后可使用邮箱/UID 登录。
39. 生产环境未配置 Resend 时，验证码接口返回明确 503；发件域名未验证或 API 拒绝时返回可诊断的 502，不影响其他已登录功能。
40. v2 旧备份可用新恢复脚本恢复；uid 为空时自动补齐，新备份包含邮箱和 UID。

## 12. 当前版本不做

- 多语言与复杂时区选择。
